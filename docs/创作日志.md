## 2026-10-28 · v1.1.0 发版

### 本轮起点
用户提出两个问题：一是批改后切换题材或年级，报告内容会消失；二是「本次批改」耗时与 tokens 的排版不好看——数值挤在中间、单位写成 `tok`、超过 60 秒仍显示秒数。

### 问题一：切题材/年级导致报告消失

**现象**：辛苦批改出来的报告，点一下年级选择就整块空掉。

**定位**：`app.js` 的 `invalidateStale()` 在检测到设置变化后直接 `S.result = null`，还同步写进了 localStorage。也就是说，结果不是「暂时没显示」，而是被真删了。

**改法**：不再删除，改为打过期标记。

```js
var source = reason === "年级" ? S.result.grade : S.result.genre;
var now    = reason === "年级" ? S.grade : S.genre;
var unchanged = source === now;
var was = !!S.result.stale;
S.result.stale = unchanged ? null : { reason: reason, at: Date.now() };
```

**过程中的失误**：第一版加了「已过期就直接 return」的提前返回，结果切走再切回原设置时标记清不掉，报告一直挂着「已过期」。改成每次都重算状态，`was` 只用来控制 toast 不重复弹，问题解决。

**提示文案重复**：报告副标题原本也写了口径提示，和过期提示条内容重叠。改成副标题固定写「视觉模型直读 · 无需本地 OCR」，口径变化只由提示条表达。

**提示条换行**：提示条一开始放在标题行里，被右侧按钮挤压，1180/1440/1920 三个档位都折成三行。移到 `#reportScroll` 顶部独占一行，三档实测都稳定两行、无溢出。

### 问题二：耗时与 tokens 排版

- 数值从中间挪到右侧，`justify-content: space-between` + `margin-left: auto`
- 单位 `tok` → `tokens`，均速 `tokens/s`
- 新增 `fmtDur(ms, digits)`：不满 60 秒保留小数秒，满 60 秒转 `1m 38s`

**边界处理**：`rest === 60` 时要进位成下一分钟，否则会出现 `1m 60s` 这种非法写法。顺带删掉了废弃的 `var secs`。

### 问题三：CSP 安全警告

Electron 启动时控制台有 Security Warning，页面缺 CSP。加了 meta 策略：

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:; connect-src *; ...
```

`connect-src *` 是必须的——用户会填任意服务商的 API 地址。加完做了冒烟验证：浏览器和 Electron 里 `ERRORS []`、无 CSP 违规、上传缩略图正常。

### 问题四：上传 GitHub 与发布 Release

**关键判断**：先核实了旧仓库 `zhipi-zzz` 是另一条独立演进线（v1.2.8、`main electron/main.js`、扁平 `assets/app.js` 3694 行），grep 确认里面没有 `fixBoardLayout` / `exportBoardHtml` / `side-cost` / `paintStaleChip` 这些本项目的核心函数。所以**不能覆盖**它，决定新建独立仓库。

**仓库重新组织**：原来网页端和桌面端各有一份代码副本，这次合并成单一源码结构，桌面端 `main.js` 改成 `path.join(__dirname, "index.html")`，不再往 `app/` 子目录找。

**打包踩坑路（这部分耗了最久）**：

1. `--cachePath` 报 Unknown argument → 改用环境变量 `ELECTRON_BUILDER_CACHE`
2. 下载 winCodeSign 失败：`There is not enough space on the disk` → C 盘满了（81G 全满，剩 0）
3. 缓存搬到 D 盘后改报 `Cannot create symbolic link : libcrypto.dylib` → 包里含 macOS 动态库的符号链接，Windows 建不了
4. 手动 `7za x -snl-` 解压无符号链接副本、重打成 7z 替换 → 每次构建的缓存目录名是随机哈希，替换了也对不上
5. 试过 `ELECTRON_BUILDER_BINARIES_MIRROR` 走国内镜像 → 下载通了，但解压仍卡符号链接
6. 想改 `binDownload.js` 走本地目录 → 调用方不传 url，走的是 `app-builder` 二进制内部的解压逻辑，改 JS 无效
7. 卡在 `updating asar integrity executable resource` 静默退出 → 还是 C 盘空间，rcedit 写 exe 要临时空间
8. 清理 C 盘 TEMP（1.4G，其中 zp-repo/node_modules 245M、dl_test.exe 95M、若干 BNZ 解压残留）腾出 1G
9. **最终解法**：`package.json` 设 `build.win.signAndEditExecutable: false`，跳过 rcedit/签名。exe 图标没了，但版本信息正常，安装包可正常安装运行

**验证**：静默安装 exit=0 → 启动安装版 → Playwright 连 CDP 查页面（标题、ZP、CSP、staleChip 全在，`pageerror` 为空）→ 读 asar 头核对内含 `paintStaleChip` / `fmtDur` / `tokens/s` / CSP。

**GitHub 权限折腾**：
- 第一道坎：令牌没有建库权限，`POST /user/repos` 返回 403 `Resource not accessible`
- 用户手动建好空仓库后，推送仍 403。测出来 `git-receive-pack` 对旧仓库 200、对新仓库 403 —— fine-grained 令牌的 Repository access 只勾了旧仓库
- 用户把新仓库加入白名单，推送一次成功

**Release 附件名**：中文名 `智批作文-1.1.0-安装包.exe` 被 GitHub 剥离成 `-1.1.0-.exe`。试了三种方式——UTF-8 percent-encoding、requests 直接发原始字节、事后 PATCH 重命名，**全都被过滤**。最终用 ASCII 名 `ZhiPi-ZuoWen-1.1.0-Setup-Win-x64.exe`，中文放 `label` 字段。

**最终校验**：从 Release 下载回来跟本地文件逐字节比对，SHA256 一致（`3abc5dcd…`），80,176,792 字节。

## 更早的积累（重构前，来自需求迭代）

这些是 v1.0 阶段反复打磨出来的约定，细节见交接文档，这里只记缘由：

- **为什么用视觉直读不用 OCR**：本地 OCR 对手写体识别不稳，且部署麻烦；直接让视觉模型读图，同时返回坐标，批注能精确贴回原句。
- **为什么导出要单页流式**：早期按 A4 强行分页，内容块会被从中间切开，页底留白也不均。改成流式后 HTML 与 PDF 共用一套结构。
- **为什么批注要两侧纵向排布**：早期按估算高度均分预留间距，卡片会重叠或偏离对应的划线。改成先清 transform 再实测高度后定位。
- **为什么演示稿和真实稿要分开**：多次出现演示数据混进真实结果、真实稿预填演示字数等问题。现在演示稿不进历史记录，真实稿上传后立刻显示真实状态。
- **为什么删掉一堆功能**：导出一开始走打印面板，用户要的是一键下载；有些入口重复堆在侧栏，改成合并。倾向做减法而不是保留隐藏入口。

## 经验沉淀

- **C 盘是这台机器的头号风险**。打包、npm、Electron 缓存全往 D 盘引；构建前先 `df -h /c` 看一眼。
- **Electron 页面截图不可靠**。Playwright 截图经常超时，一律用 `evaluate` + `getBoundingClientRect` 量真实数值。
- **视觉评审模型的结论不能当证据**。多次把细微间隙判成重叠、把截图取景边界判成裁切，都靠实测坐标推翻。
- **「构建成功」不等于「可交付」**。必须装一遍、启动一遍、查一遍 asar 里的内容。
- **GitHub 的 fine-grained 令牌是按仓库授权的**。新建仓库后必须把它加进令牌的白名单，否则 API 显示的 `push: true` 是账户权限，不代表令牌能推。
