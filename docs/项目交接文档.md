## 一、一句话说明

面向小学高年级到初中的 AI 作文批改工作台：上传作文（图片或文字）→ 视觉模型直读 → 四维评分 + 双侧逐句批注 + 写作思路 / 小练笔 / 升格范文 → 导出所见即所得的白板报告。纯前端，无后端无数据库，数据只存本机；同时打包为 Electron 桌面版。

## 四、核心机制

### 4.1 命名空间
全部挂在 `window.ZP` 上，无构建工具、无模块系统，靠 `<script>` 顺序加载。新增模块时：在 `index.html` 加 `<script>`（放在依赖之后），文件内写 `(function(){ ... })()` 并挂到 `ZP`。

### 4.2 AI 调用
- 统一走 OpenAI 兼容协议，`ZP.chat()` 封装。
- 服务商预设见 `config.js` 的 `ZP.PROVIDERS`：DeepSeek / 通义千问 / Kimi / 智谱 / OpenAI / 豆包（火山方舟）/ 自定义。
- 视觉模型单独一套预设（用于读手写作答）：通义 Qwen-VL、智谱 GLM-4V、Kimi 视觉、硅基流动、OpenAI 等。
- 火山方舟接口需带 `thinking: {type: "disabled"}`，否则会返回思考内容干扰 JSON 解析。
- **两阶段批改**：阶段一 `ZP.gradeEssay()` 出评分与批注；阶段二 `ZP.polishEssay()` 出升格范文。
- **JSON 容错**：`jsonComplete()` 检查截断 → `continueIfTruncated()` 续写 → `parseJSON()` / `balanceJSON()` 做补括号修复。模型偶发输出不合法 JSON 时靠这套兜底，不要绕过。

### 4.3 视觉直读
不做本地 OCR，直接把图片交给视觉模型，返回结果带坐标：`box: {y, x1, x2}` + `page`（多页稿）。批注按坐标贴回原稿。`local_ocr/` 是内网离线场景的可选备选，默认不启用。

### 4.4 状态与持久化
- 单一状态对象 `S`（`app.js`），包含：当前稿、稿件队列 `S.docs`、批改结果 `S.result`、年级 `S.grade`、题材 `S.genre`。
- localStorage 键：`zhipi.docs.v1`（稿件队列 + 结果）、`zhipi.history.v1`（历史记录）。配置另有独立键。
- **持久化必须覆盖结果本身**，不能只存原稿和标题；否则刷新后报告会丢（曾踩过这个坑）。
- 演示稿的历史记录**不写入** `zhipi.history.v1`，与真实批改严格分开。

### 4.5 过期标记（v1.1.0 重点改动）
改年级或题材后，**不清空**结果，而是打过期标记：

```js
// app.js  invalidateStale(reason)
var source = reason === "年级" ? S.result.grade : S.result.genre;
var now    = reason === "年级" ? S.grade : S.genre;
var unchanged = source === now;
var was = !!S.result.stale;
S.result.stale = unchanged ? null : { reason: reason, at: Date.now() };
```

关键点：
- 每次都重算（不能提前 return），否则「切走再切回」时分不清该不该清标记。
- `was` 只用于控制 toast 不重复弹。
- 标记渲染在 `#reportScroll` 顶部的 `#staleChip`，独占一行；**不要**放回标题行，会被右侧按钮挤成三行。
- 批改完成、`loadHistory`、`loadDoc`、刷新恢复、分数覆盖处都要调 `paintStaleChip()`。

### 4.6 画板批注排布
`fixBoardLayout()` 先清空元素的 transform，再量真实高度，然后排布卡片。**不清 transform 会量到缩放后的尺寸**，排出来的位置全错。

### 4.7 耗时与用量
- `fmtDur(ms, digits)`：`<60s` 保留小数秒；`≥60s` 转 `m s` 形式（`1m 38s`），`rest === 60` 要进位，不能出现 `1m 60s`。
- 单位统一 `tokens` / `tokens/s`，不要写 `tok`。
- 耗时卡数值列右对齐、标签与数值两端对齐，长数值不折行。

### 4.6.1 移动端阅读
导出页带 `viewport` meta；`.doc` 固定逻辑宽 1032px，窄于该宽度时在 `#docWrap` 内整体 `scale()` 等比缩放（`fitMobile()`），
外层容器高度按 `内容高 × 比例` 设置，保证手机上能上下滑动读完整、无横向溢出。
量高度前必须先 `transform='none'` 复位，否则读到的是缩放后的尺寸。桌面端（≥1032px）不缩放，版式不变。

### 4.8 导出
`report-export.js` 走**单一渲染路径**：单页流式、不按固定页高强行分页；HTML 与 PDF 共用同一套结构，避免某条路径缺区块。导出时批注卡与作文纸位置严格对齐，不因响应式变回静态流式。

### 5.2 桌面端打包（本机特有约束）

本机 C 盘空间极度紧张（曾只剩 2MB），打包有若干坑，**必须按下面的方式执行**：

```bash
cd <源码目录>
ELECTRON_BUILDER_CACHE="D:/ankhd/Documents/Raccoon/build/ebcache" \
TMP="D:/ankhd/Documents/Raccoon/build/tmp" \
TEMP="D:/ankhd/Documents/Raccoon/build/tmp" \
./node_modules/.bin/electron-builder --win nsis --x64 \
  --config.electronDist="D:/ankhd/Documents/Raccoon/build/edist" \
  --config.directories.output="D:/ankhd/Documents/Raccoon/build/distNNN"
```

踩过的坑（按顺序）：

1. **`--cachePath` 不是合法参数** —— 用环境变量 `ELECTRON_BUILDER_CACHE`。
2. **C 盘满导致下载失败** —— 缓存、TMP、TEMP 全部指到 D 盘。
3. **winCodeSign 解压失败**（`Cannot create symbolic link`）—— 包内含指向 macOS dylib 的符号链接，Windows 无权限创建。处理：用 `7za x -snl-` 解压一份无符号链接的副本，重打成 7z 替换缓存中的同名文件。
4. **`app.asar` EBUSY** —— 上一轮构建残留进程占用，换输出目录重来。
5. **卡在 `updating asar integrity executable resource`** —— 这是 rcedit 写 exe 资源，需要临时空间；C 盘满会静默卡死。清 C 盘缓存后解决。
6. **最终起作用的开关**：`package.json` 里设 `build.win.signAndEditExecutable: false`，跳过 rcedit/签名。副作用是 exe 图标不写入（版本信息仍正常），安装包本身可正常安装运行。

`electronDist` 指向 `D:/ankhd/Documents/Raccoon/build/edist`（预下载的 Electron 二进制），因为直接复制 `electron.exe` 会被拦。

### 5.3 验证清单（每次发版必跑）

```bash

powershell -c "Start-Process -FilePath '<安装包>.exe' -ArgumentList '/S','/D=D:\...\installtest' -PassThru -Wait"
```

另需核对 asar 内容确为本轮改动（读 `resources/app.asar` 的头，按 offset 取文件内容，grep 关键函数名），**不能只看打包成功**。

## 八、协作约定（重要，违反会返工）

- 修复类改动**先定位根因**，不做补丁式微调；同一处反复调参说明方案不对，应整体重写成清晰实现。
- 布局类问题**由浏览器完成排版后实测真实尺寸**，不用公式估算元素高度做绝对定位。
- 交付前**实际启动**验证，不把「构建成功」当「可交付」。
- 结论以实测数据（坐标、尺寸、字节数、哈希）为准，不凭截图观感。
- 面向学生的文案统一称「小作者」，产物中不出现「AI」「智能批改」等字样。
- 做减法优先：不用的功能彻底删除（含代码、样式、依赖），不保留隐藏入口。
